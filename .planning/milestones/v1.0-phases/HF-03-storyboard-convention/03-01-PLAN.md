# Phase 3 / Plan 03-01 — Storyboard + meta.json convention + beat-timeline approval gate

Schema + manifest + skill phase. No new Python orchestrator. Read
`schemas/artifacts/scene_plan.schema.json` and `edit_decisions.schema.json` FIRST to match
house style (JSON draft 2020-12, `$id` `openmontage/artifacts/<name>`, `version` const,
`additionalProperties` discipline). Read `schemas/artifacts/__init__.py` to see how schemas
are registered/discovered and register the two new schemas the same way.

## Task 1 (tracer) — storyboard schema + one valid example, validated

1. Write `schemas/artifacts/storyboard.schema.json` per CONTEXT D-01:
   top-level `version` const "1.0", `total_seconds`, optional `music_bed`, and `beats[]`
   where each beat = `{id, start_seconds, duration_seconds, on_screen (label), vo?,
   sfx?: [{at_seconds, cue}], music?: [{at_seconds, level_db, reason}]}`. Required keys
   sensible; match the `additionalProperties` posture of the neighbouring schemas.
2. If `schemas/artifacts/__init__.py` enumerates schemas (list/registry), add `storyboard`.
3. Author a minimal valid example storyboard (e.g. `schemas/artifacts/examples/storyboard.example.json`
   OR inline in a test) and VALIDATE it against the schema with the repo's validator
   (jsonschema draft 2020-12). Tracer DoD: schema parses, `$schema`/`$id` correct, example
   validates GREEN. Commit atomically.

## Task 2 (expansion) — meta.json + STORYBOARD.md convention + the approval gate

1. `schemas/artifacts/project_meta.schema.json` (D-02): `{version const, fps, resolution:
   {w,h} or aspect, tts: {provider, voice_id}, music_bed?, room_tone_dbfs?, ...}`. Register
   in `__init__.py` like Task 1. Add a filled example `meta.json` (validated) that matches
   a real `projects/<name>/` shape.
2. STORYBOARD.md convention: add a short template + "how to author" note (house convention
   — follow how OM documents artifacts; a `styles/`-style template file or a director note,
   planner's discretion). It renders the storyboard beats for human review.
3. **Beat-timeline approval gate (D-03, STORY-03):** in `pipeline_defs/screen-demo.yaml`,
   on the `scene_plan` stage, set `checkpoint_required: true` + `human_approval_default:
   true` and add `storyboard` to its `produces`. Do the same on the beat-timeline/scene_plan
   stage of `pipeline_defs/animated-explainer.yaml`. Verify YAML still parses.
4. Add a section to `skills/meta/checkpoint-protocol.md`: the beat-timeline / storyboard is
   a MANDATORY human-approval gate that must pass BEFORE the `assets` stage spends on
   generation/render. Keep it consistent with the existing protocol table.
5. **Verify:** both schemas parse + examples validate; `screen-demo.yaml` and
   `animated-explainer.yaml` parse and their scene_plan stage has `human_approval_default:
   true` + `produces: storyboard`; checkpoint-protocol documents the gate; ASCII-only
   punctuation everywhere. Commit atomically.

## Definition of Done
- `storyboard.schema.json` + `project_meta.schema.json` exist, draft-2020-12, registered,
  each with a validated example.
- screen-demo + animated-explainer beat-timeline stage carries the human-approval gate and
  produces `storyboard`.
- checkpoint-protocol.md documents the pre-asset beat-timeline gate.
- All new/edited content ASCII-clean; YAML + JSON parse.
